packset

The loopback writer for standing knowledge: one process owns the pack, and every client speaks HTTP to it.

Install

The CLI starts and inspects the writer. The writer is a second binary, packsetd, which packset finds beside itself or on PATH.

cli + writer 
cargo install --git https://github.com/leidarljos/packset packset-cli packset-daemon

PACKSET_URL is the contract. packset ensure starts the writer if it is down and prints that URL.

Commands

From packset --help. Lifecycle first, then the /v1 reads a shell runs.

CommandDoes
packset ensure Start if down, then print the URL.
packset start Start the writer.
packset stop Stop the writer this seat started.
packset status Counts by kind, the pinned set, the index.
packset which The packsetd this seat would start.
packset url Print PACKSET_URL.
packset pin NAME Read, or set, the pinned set. Needs a workspace.
packset atoms WORKSPACE Live-now atoms, one JSON object a line. --as-of TS for those live at that time.
packset accessions WORKSPACE Deed accessions live atoms cite, one per line.
packset citers ACCESSION WORKSPACE The live atoms citing one accession.
packset export --into DIR WORKSPACE Atoms to a satchel; cited accessions to stdout.

Name a workspace on the command, or set PACKSET_WORKSPACE. accessions pipes into deedar evidence - or deedar current -.

cited accessions, then the bytes 
packset accessions WORKSPACE | deedar evidence -

Alone, or through ljos

Use packset when the job is the writer itself: start it, pin a set, list atoms, export a satchel, or walk the accessions a pack cites. Other projects that only need standing knowledge speak this crate and ignore the seat.

Use ljos when an agent must write or retrieve through the seat and not invent another store. ljos remember / ljos prefer POST one explicit claim. ljos search retrieves. The seat does not start the writer, pin a set, or export.
