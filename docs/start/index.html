First write

A reader who has never used the seat can finish this page with one lesson in the pack, the same text coming back from search, and a review clock running on it.

Install every binary this walk uses

$ cargo binstall ljos ljos-mcp packset packset-daemon deedar-cli claimdag-cli vissue-cli ljos-consensus ljos-policyd
$ command -v ljos ljos-mcp packset packsetd deedar claimdag vissue ljos-consensus ljos-policyd

You should see nine paths. If packsetd is missing, step 3 has no writer to start. cargo install <crate> works if you do not have cargo-binstall.

Remember without a writer fails

$ ljos remember "the default fuse is CombMNZ"
Error: remember: the pack writer did not answer at http://127.0.0.1:8761 ...

That error is the first success. The seat will not invent a store, and it does not report a writer that is down as an empty pack.

Start the writer

$ packset ensure
$ ljos doctor
ok	pack	http://127.0.0.1:8761 workspace seat
ok	host key	...
ok	deed store	size=0 root=...
ok	tracker	vissue 0.11.0
ok	claim graph	...

Nothing to export. The seat finds the writer on 127.0.0.1:8761 from any directory, and its memory is the one workspace seat. If the pack row says no, stop. Do not continue.

Write one claim, then retrieve it

$ ljos remember "the default fuse is CombMNZ"
{
  "kind": "lesson",
  "level": "explicit",
  "text": "the default fuse is CombMNZ",
  "id": "156eb2be9898...",
  "due_at": "2026-09-13T09:12:00.000Z"
}
$ ljos search fuse
1.0000  lesson  156eb2be9898...  the default fuse is CombMNZ
$ ljos due
0 due; 1 scheduled, next at 2026-09-13T09:12:00.000Z

You should see kind of lesson, the same sentence in the search hit, and a review scheduled a day out. That is the retrieve and the clock. If search is empty, the write did not land. Tomorrow ljos due lists the claim; ljos graded ID (or --lapsed) moves the clock.

Prefer is the same path

$ ljos prefer "never extract on write"
$ ljos search extract
1.0000  preference  ...  never extract on write

Cards print files. They do not write them

$ ljos cards --dir /tmp/demo

With no USER.md or MEMORY.md, the command prints nothing and exits

  1. That is not a failure.

Hand it to an agent

$ ljos protocol | head -3
# The seat protocol

One seat, five stores, five questions. Ask the store that owns the question.
$ ljos onboard --harness json

The protocol is the text an agent reads before any work: which store answers which question, the order of verbs in a sitting, the refusals. onboard prints the server entry for any runner, or registers the server, installs the protocol as a skill, and installs the memory hook for a runner named in ~/.config/ljos/harnesses.toml. Harnesses shows the file.
