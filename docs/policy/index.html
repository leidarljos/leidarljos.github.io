Policy

The model is not the gate.

ljos-policyd prints allow or deny. The harness hook calls it. Reloading a pack is not a check. Absence is not a deny.

Check a line

$ cargo binstall ljos-policyd
$ ljos-policyd check -- cargo test
allow
$ ljos-policyd check -- sudo id
deny	sudo

First matching deny wins. A deny exits 2. exec runs the line only on allow.

Ask the seat

$ ljos policy -- ls
ls
allow
$ ljos doctor

Doctor names the policyd row when the binary answers. POLICYD_BIN points at a binary that is not on PATH. POLICYD_REQUIRED=1 is fail-closed.

The hook

ljos hook reads the action about to happen and prints the memories it activates. It also returns a pack-rule verdict when one matches. ljos onboard installs it on the runner's tool-call and prompt events. Nothing to say is no output. The hook never blocks an action; the TCB binary does.

Pack rules beside the TCB

$ ljos rule '*--force*' --verdict deny --why "Never force push."
$ ljos policy -- git push --force

A rule is memory: dated, supersedable, exported in a handover. It cannot allow what ljos-policyd denied. Edit a rule only when argv law itself changes.
