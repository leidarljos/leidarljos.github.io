Write one claim. Search it back.

ljos gives coding agents such as Claude Code, Codex, and Cursor a memory, a work tracker, and a check on every shell command. It writes one claim when you say Remember: or Prefer:, then searches that claim back. Nothing is mined from chat, and memory stays on your machine unless you turn on a remote judge.

Why this exists

Agents forget, remember the wrong things, and run any command.

They forget

Each session starts cold. The fix you agreed on yesterday, the rule about force pushes, the reason a test is skipped: gone unless someone pastes it back in.

Auto-memory fills with things nobody said

Tools that mine the transcript keep whatever a model guessed was worth keeping, including text that came from a web page or a tool result. That is how memory gets poisoned.

Shell commands run unchecked

A coding agent with a shell can push, delete, or pipe a download into sh on its own judgement.

ljos writes a memory only when you say Remember: or Prefer:, keeps it in plain local files you can read, and checks each shell command against fixed rules before it runs. No model sits in the write path or the check, and it all runs on a CPU.

The loop

Sit, work, finish.

ljos words: a seat is one agent runner on one machine, with its memory and claims. A sitting is one piece of work on one ticket. A deed is a hashed record of what that work produced. packset is the memory store that search reads, and vissue is the tracker, plain Org files in git. leiðarljós is Icelandic for a guiding light.
