deedar

A unit of work produces something; deedar records it as a deed — here is the work, this is its identity, take it.

Install

cli 
cargo install --git https://github.com/indynull/deedar deedar-cli

There is no daemon. Each command opens the store at DEEDAR_URL or --url. quote, patch, and file are kinds. Next work takes deed ids as --input.

Commands

From deedar with no verb. evidence, current, and export take one id, several ids, or - to read them from stdin.

create a file deed 
deedar create file \
  --id deed-file-note \
  --name "the note" \
  --path note.md \
  --media text/plain \
  --agent reader
CommandDoes
deedar get ID The named frozen deed. Also accepts a unique sha256:.
deedar list Every deed in the store.
deedar trail ID Walk --input from this deed to what it cites.
deedar evidence ID Check the deed, its write-once bytes, and every source. Several ids, or -.
deedar current ID Follow --supersedes to the tip. Exits non-zero when any named deed moved.
deedar leave ID DEST Copy the file bytes to DEST/{id}/ with a hash sidecar.
deedar timestamp ID Write an RFC 3161 TimeStampReq over the evidence bytes.
deedar export --into DIR ID Canonical bytes, evidence, and a proof.txt against the log head.
deedar check DIR The receiving end. Needs no store. Optional --since BRIDGE.
deedar log head What a reader keeps between visits. Also list, audit, prove ID, bridge SIZE.
deedar migrate Write {store}/layout when that file is missing.

delete writes a tombstone; evidence on that id then fails. vouch sign FILE / vouch check FILE cover the manifest of a bag.

Alone, or through ljos

Use deedar to create a deed, walk a trail, leave bytes, timestamp, or hand a bag to somebody else. A store that only freezes product speaks this crate and ignores the seat.

Use ljos when the seat should ask whether cited bytes are intact or still the tip. ljos evidence and ljos current exec the same verbs. Creating, exporting, and checking a bag stay on this crate.
